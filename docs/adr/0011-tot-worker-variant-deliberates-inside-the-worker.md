# ToT worker variants deliberate inside the worker, behind a flag

`TextHookAgent` and `CreativeDirectionAgent` gain alternate **Tree-of-Thoughts variants**
selected by a per-worker `tot_enabled` flag (the legacy single-pass agents stay callable as
fallback/baseline — REQ-13/14). The search controller lives **inside the worker**: one dispatch
still returns one proposal of the existing shape, so ADR [0008](./0008-director-dispatches-workers-in-loop.md)'s
dispatch contract is untouched — the Director sees `dispatch_text_hook` → `HookProposal` and
`dispatch_creative_direction` → one direction document exactly as before. The worker simply fires
many model calls internally and **self-caps** them with its own `max_llm_calls` budget (default 40)
as a runaway/cost stop.

The tree is **depth-2** for both: an upstream *frame* stage (a **payoff frame** for hooks, a
**creative concept** for direction) generated by `sample` and pruned, then an execution stage
(hook phrasings / the beat-by-beat map). Evaluation is **hybrid** by default — `value` at the frame
gate (judgeable in isolation against the transcript/brand) and `vote` at the execution gate
(comparative, no ground truth) — run on a separate cold-temperature call so no completion grades its
own output (REQ-7). Search is **BFS by default, DFS also available** via a worker constant; DFS
backtracks to the next frame only when the current frame's best candidate fails a hard constraint or
scores below `dead_end_threshold`.

## Considered Options

- **In-prompt simulated ToT** (one completion narrates the whole tree) — rejected: violates
  evaluator independence (the model rubber-stamps itself), leaves no real tree to log or budget, and
  its ~1-call cost signature isn't the order-of-magnitude cost real ToT carries.
- **Director-as-orchestrator** (the Director runs the search loop; workers become per-node
  generators) — rejected: it would retire ADR 0008 and split authoring across the search loop.
- **Add `n`/`temperature` to the `ModelClient` seam** — rejected: it ripples to every client and
  test stub. Instead ToT workers pin to Gemini and hold two client instances (a hot generator
  ~0.9, a cold evaluator ~0.1). The default no-API-key `ClaudeCodeClient` (ADR
  [0006](./0006-claude-code-via-agent-sdk-as-single-turn-model.md)) exposes no sampling knob, so it
  cannot host a ToT worker — **ToT workers are Gemini-only.**

## Consequences

- **The Director's budgets are unaffected.** A ToT dispatch costs exactly one unit of the Director's
  dispatch budget regardless of how many Gemini calls run inside it; the worker's internal
  `max_llm_calls` is a separate, self-contained budget the Director neither sees nor counts. The two
  budget systems do not interact.
- One dispatch runs ≈10–25 internal model calls (value evaluation dominates: `k` frames ×
  `n_evaluate`). `max_llm_calls` is the hard runaway stop.
- The returned proposal stays lean (ranked hooks; a single winning direction), but the worker logs
  the full tree internally — all thoughts, scores, and pruned branches (REQ-11) — via the existing
  `tracing` / `log` seam.
