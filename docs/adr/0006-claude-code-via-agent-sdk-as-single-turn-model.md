# Claude Code authoring via the Agent SDK driven as a single-turn JSON model

The authoring `ModelClient` seam ([0004](./0004-tool-driven-incremental-authoring.md)) is synchronous and *we* own the loop: the model only proposes one turn, and the `AuthoringLoop` applies it, journals it, and feeds perception back. The **Claude Agent SDK** is the opposite shape — an agent *harness* that owns its own tool-use loop, executes tools in-process, runs async-only, and authenticates through the **Claude Code CLI** rather than an `ANTHROPIC_API_KEY`. We wanted that CLI-auth path (no per-token billing, no separate API rate limits), so `ClaudeCodeClient` reconciles the two by using the SDK as a **single-turn JSON generator**: each `next_turn` runs a one-shot `query` with `max_turns=1` and no SDK tools, serializes our neutral history plus the tool schemas into the prompt, and asks the model to emit exactly one tool call as JSON `{"name", "args"}`, which we parse back into a neutral `AssistantTurn`. The async `query` is driven from the synchronous seam with stdlib `asyncio`. The loop, journal, finalization gate, and op budget are untouched, and it is the default authoring client.

Two consequences are deliberate. **Vision tools (`render_still`/`scene_preview`) are hidden** from this client — the one-shot text query has no image-return channel — so it authors from structured-text perception only (valid under [0004](./0004-tool-driven-incremental-authoring.md); full-motion judgement still happens in the finalization gate through the video-capable `ReviewAgent`, which Gemini still serves). And there is **no native tool-use recovery channel**, so a hard JSON-parse failure ends the turn with an empty `AssistantTurn` and the loop stops, exactly as it would for any model that stopped calling tools; a tolerant parser (fence-stripping, first-object extraction) mitigates this.

## Considered Options

- **SDK owns the loop (its native shape)** — rejected: it would fork the authoring runtime, giving us two loops, two journaling paths, and the gate/budget invariants reimplemented for one provider. Keeping every provider behind the same single-turn seam keeps the `AuthoringLoop` the single source of truth.
- **Anthropic Messages API (`AnthropicModelClient`)** — already exists and supports native tool use and vision, but needs an API key. `ClaudeCodeClient` is the no-API-key sibling; both remain available and swappable.
